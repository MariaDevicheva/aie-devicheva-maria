## 2. Структура проекта

Проект организован в следующей структуре:

- `requirements.txt` – зависимости проекта (библиотеки Python, необходимые для запуска).
- `report.md` – отчёт по проекту (постановка задачи, данные, эксперименты, результаты).
- `self-checklist.md` – чеклист самопроверки проекта перед сдачей.
- `notebooks/` – экспериментальные ноутбуки:
  - EDA, прототипы моделей, отдельные эксперименты.
- `src/` – основной код проекта:
  - модули для работы с данными;
  - обучение моделей;
  - запуск сервиса/скриптов.
- `data/` – демонстрационные/учебные данные:
  - **только открытые, синтетические или обезличенные данные;**
  - при необходимости – небольшие выборки для быстрого запуска.
- `configs/` – конфигурационные файлы:
  - `.yaml`, `.json`, `.env.example` и т.п.
- `tests/` – тесты (юнит-тесты, простые проверки).
- `artifacts/` – сохранённые модели, отчёты, результаты экспериментов.

Если структура проекта отличается от базовой, опишите это здесь.

## 3. Требования и установка

### 3.1. Требования

- Python `>= 3.10` (уточните при необходимости).
- Установленные системные зависимости (если есть: например, `git`, `make` и т.п.).

### 3.2. Установка окружения

```bash
# Перейти в папку проекта
cd project

# Создать виртуальное окружение
python -m venv .venv

# Активировать окружение

# Windows
.venv\Scripts\activate

# Linux / macOS
source .venv/bin/activate

# Обновить pip
python -m pip install --upgrade pip

# Установить зависимости
pip install -r requirements.txt
```

### Дополнительные компоненты

Для отслеживания результатов экспериментов используется **MLflow**.

Запуск интерфейса MLflow:

```bash
mlflow ui
```

После запуска интерфейс будет доступен по адресу:

```text
http://127.0.0.1:5000
```

Для работы сервиса требуется предварительно обученная модель:

```text
artifacts/price_optimizer.pkl
```

Модель формируется в процессе выполнения ноутбука:

```text
notebooks/02_model_training.ipynb
```

В ноутбуке выполняются:

- обучение моделей машинного обучения;
- сравнение результатов по метрикам;
- логирование экспериментов в MLflow;
- сохранение финальной модели для последующего использования API-сервисом.

## 4. Как запустить проект

Проект включает этап обучения модели, отслеживание экспериментов с помощью MLflow и запуск REST API сервиса для получения рекомендованной цены товара.

### 4.1. Запуск обучения модели

```bash
cd project

# Активировать виртуальное окружение

# Windows
.venv\Scripts\activate

# Linux / macOS
source .venv/bin/activate
```

Открыть ноутбук:

```text
notebooks/02_model_training.ipynb
```

и выполнить все ячейки последовательно.

В результате будут выполнены:

- обучение моделей машинного обучения;
- сравнение моделей по метрикам качества;
- логирование экспериментов в MLflow;
- сохранение финальной модели.

Финальная модель сохраняется в:

```text
artifacts/price_optimizer.pkl
```

### 4.2. Просмотр результатов экспериментов в MLflow

Запуск интерфейса MLflow:

```bash
mlflow ui
```

После запуска интерфейс доступен по адресу:

```text
http://127.0.0.1:5000
```

В MLflow отображаются результаты экспериментов для моделей:

- Linear Regression;
- Ridge Regression;
- Random Forest Regressor;
- XGBoost Regressor.

---

### 4.3. Запуск сервиса (API)

```bash
cd project

# Windows
.venv\Scripts\activate

# Linux / macOS
source .venv/bin/activate

uvicorn src.main:app --reload
```

После запуска сервис будет доступен по адресу:

```text
http://127.0.0.1:8000
```

Swagger UI:

```text
http://127.0.0.1:8000/docs
```

---

### 4.4. Запуск через Docker

Сборка контейнера:

```bash
docker build -t price-monitoring-system .
```

Запуск контейнера:

```bash
docker run -p 8000:8000 price-monitoring-system
```

или

```bash
docker-compose up --build
```

---

### Реализованные endpoints

#### GET /

Информация о сервисе.

#### GET /health

Проверка работоспособности сервиса.

Пример:

```text
http://127.0.0.1:8000/health
```

#### GET /metrics

Метрики Prometheus для мониторинга работы сервиса.

Пример:

```text
http://127.0.0.1:8000/metrics
```

#### POST /predict

Получение рекомендованной цены товара.

Пример запроса через Swagger UI:

```text
http://127.0.0.1:8000/docs
```

Сервис принимает характеристики товара и рыночные параметры, после чего возвращает прогноз оптимальной цены.

---

### Проверка работоспособности

1. Открыть Swagger UI:

```text
http://127.0.0.1:8000/docs
```

2. Выполнить тестовый запрос к `/predict`.

3. Проверить статус сервиса:

```text
http://127.0.0.1:8000/health
```

4. Проверить метрики:

```text
http://127.0.0.1:8000/metrics
```

Если все endpoints отвечают корректно, сервис считается успешно запущенным.

## 5. Данные

Для реализации проекта используется синтетически сгенерированный набор данных, имитирующий реальные данные о товарах и конкурентных ценах на рынке розничной торговли.

Источник данных:

- собственная генерация данных;
- данные созданы для демонстрации работы системы мониторинга и анализа конкурентных цен.

Основной файл данных:

```text
data/sample_data.csv
```

Набор данных содержит следующие характеристики:

- текущая цена товара;
- средняя цена конкурентов;
- минимальная цена конкурентов;
- максимальная цена конкурентов;
- количество конкурентов;
- категория товара;
- целевая (оптимальная) цена.

Для анализа данных и обучения моделей используются ноутбуки:

```text
notebooks/01_data_generation_and_eda.ipynb
notebooks/02_model_training.ipynb
```

В репозитории хранятся только небольшие демонстрационные данные, необходимые для воспроизведения проекта.

Проект не использует персональные данные и не содержит конфиденциальной информации.

## 8. Ограничения и дальнейшая работа

### Текущие ограничения

В текущей версии проекта имеются следующие ограничения:

- используется синтетически сгенерированный набор данных;
- отсутствует автоматический сбор цен конкурентов из внешних источников;
- не реализована интеграция с маркетплейсами и интернет-магазинами;

- отсутствует система авторизации пользователей.

- развёртывание в облачной инфраструктуре;
